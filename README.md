# 🌍 mmo-proto

浏览器里跑一个 3D 联机世界的技术原型。

**目标**：验证「把游戏搬进浏览器 + 联机」这条技术路线。

---

## 这是什么

一个最小可用的 3D MMO 原型：

- **客户端**：Three.js（WebGL）渲染 3D 场景，第一/第三人称跟随相机
- **服务端**：Node.js 手写 WebSocket（零第三方依赖），处理登录、位置同步、聊天
- **联机**：多人同屏，能看到彼此走动、聊天

> 注意：这不是《魔兽世界》的复刻，是独立的技术验证项目。
> 目标是跑通「浏览器 + 3D + 联机」这条链路。

---

## 玩法

打开两个浏览器窗口，各输一个名字，就能互相看见。

| 操作 | 按键 |
|---|---|
| 移动 | `W` `A` `S` `D` 或方向键 |
| 奔跑 | `Shift` |
| 转视角 | 鼠标拖动 |
| 拉近拉远 | 滚轮 |
| 聊天 | `Enter` 打开输入框，`Esc` 取消 |

手机端：拖动屏幕转视角（移动端虚拟摇杆待补）。

---

## 本地运行

```bash
node server/server.js
```

然后浏览器打开 `http://localhost:8896/`

默认端口 8896，可用环境变量覆盖：

```bash
PORT=9000 node server/server.js
```

## 技术细节

### 服务端

- **零依赖**：WebSocket 握手和帧编解码全部手写（RFC 6455）
- **Tick 20Hz**：每秒 20 次全量广播玩家状态
- **反作弊**：移动速度限速（最快 12 米/秒），超速拉回
- **世界边界**：200×200 米
- **上限 64 人**

协议是 JSON 明文，简单直白：

```js
// 客户端 → 服务端
{ t: 'login', name: '名字' }
{ t: 'move', x: 1.2, z: -3.4, ry: 0.5 }
{ t: 'chat', text: '你好' }
{ t: 'ping', c: 123456 }

// 服务端 → 客户端
{ t: 'hello', tick: 20, world: {...} }
{ t: 'welcome', id: 1, name: '...', players: [...] }
{ t: 'join' | 'leave', p: {...} | id: 1 }
{ t: 'state', players: [...] }
{ t: 'chat', id: 1, name: '...', text: '...' }
{ t: 'pong', c: 123456 }
```

### 客户端

- **Three.js 0.160**（CDN 加载，ESM）
- 场景：程序生成的起伏地形、150 棵树、80 块石头、中央方尖碑
- 角色：胶囊体 + 球头 + 朝向锥 + 双腿 + 脚下发光圈
- **平滑插值**：别人移动时用位置插值，不会一跳一跳
- **相机**：第三人称跟随，用 `lerp` 做平滑

## 已知限制

- 没有物理碰撞（能穿过树和石头）
- 没有战斗系统
- 没有持久化存储（服务器重启后玩家数据清空）
- 移动端虚拟摇杆还没做
- 服务端必须开 WebSocket 端口，纯静态托管跑不了联机

## 下一步方向

1. 物理碰撞（AABB / 圆柱碰撞）

3. 简单的战斗（血量、伤害、死亡）
4. 持久化（SQLite）
5. 区域分服（减少广播压力）
